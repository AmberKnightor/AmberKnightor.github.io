Конструкторские бюро

Чертежи, ведомости и комплекты для производства выпускаются быстрее и с меньшим числом ручных операций, в которых можно ошибиться.

Команды, работающие в Tekla

Рутина автоматизирована, и вся команда работает одними инструментами и по одним стандартам.

Проблема

Каждая выдача металлоконструкций уходит на завод комплектом: контуры листовых деталей для плазменной или лазерной резки, геометрия труб для трубореза, сборочные чертежи, ведомости и бирки отправочных марок. Если делать это вручную в Tekla, это часы выгрузки, переименования, раскладывания по папкам и сверки количества — а одна пропущенная деталь останавливает производство.

  • Листы — DXF на каждую позицию с читаемой маркой, по маркам стали и толщинам
  • Трубы — STEP/IGES в локальных координатах, косые резы приведены к технологичным, марка гравируется
  • Чертежи — сборочные чертежи и чертежи гнутых деталей с видами, разрезами и размерами
  • Ведомости — настоящие .xlsx, каждый файл сверяется с ведомостью перед отправкой

Кейс: команда конструкторов металлоконструкций

Одна выдача в производство одним конструктором: около 3,5 часа вручную и около 30 минут с инструментами.

Задача

Каждый шаг делался вручную или через несколько программ. Создавались чертежи пластин, марки передвигались вручную, затем чертежи печатались. Трубы проходили через встроенный в Tekla MultiConverter, потом через скрипты Grasshopper, чтобы выпрямить косые резы и добавить гравировку. Сборочные чертежи делались по одному.

Решение

Три связанных инструмента, которые запускаются прямо из Tekla: Report checker для пластин и ведомостей, Convertstp для труб, Drawer для чертежей. Косые резы выпрямляются, а марки гравируются автоматически, результат сверяется с ведомостями, поэтому человеку больше не нужно ловить расхождения глазами.

Инструменты

Три настольных приложения для ежедневной работы на производстве. Скриншоты ниже — настоящие программы; на них показан английский вариант интерфейса.

Report checker

Выгрузка пластин в DXF, отчёты Tekla в .xlsx и сверки · Python + помощник на C#

  • DXF прямо из модели. Консольный помощник на C# управляет Tekla через Open API: Tekla пишет DSTV (NC1) для выбранных пластин, а помощник переводит их в DXF R12 — контур, вырезы, круглые и овальные отверстия на отдельных слоях.
  • Марка никогда не попадает на отверстие. Марка позиции ставится в самое большое свободное место пластины и при необходимости уменьшается; отдельная функция переносит марки, которые пересекают геометрию в уже готовых файлах.
  • Отчёты без макросов Excel. Шаблоны отчётов Tekla запускаются по выбору и пересохраняются как оформленные .xlsx (сама Tekla пишет только HTML с расширением «.xls»).
  • Проверки, которые ведут обратно в модель. Папки DXF и STEP сверяются с ведомостями — недостающие, лишние файлы и файлы с неверным количеством выводятся списком, а детали выбираются в Tekla.
  • Папки, готовые для завода. Файлы переименовываются в позиция_толщина_кол-во, раскладываются по маркам стали, толщинам, типам труб и профилям; бирки формируются в DXF.
  • Все версии Tekla с 2016. Сборки Open API загружаются из запущенной Tekla, при старой и новой структуре папок, поэтому один exe работает у всей команды.

Convertstp

Трубы из Tekla → STEP / IGES для лазерной резки труб · C# WinForms

  • Настоящая геометрия, а не догадка по профилю. Каждая труба проходит через собственный экспорт IFC в Tekla, переносится в локальную систему координат детали и переводится в STEP или IGES (IfcConvert и собственный модуль записи IGES с обрезанными гранями и точными дугами).
  • Технологичные резы. Косые резы стенки, которые лазер не может выполнить, выпрямляются; седловые резы, пазы под пластины и пересечения круглых труб обрабатываются отдельно.
  • Гравировка в геометрии. Марка детали вырезается на широкой грани трубы — по поверхности или насквозь через стенку, — а модель Tekla при этом не меняется.
  • Предпросмотр всей партии. HTML-страница показывает каждую трубу в масштабе с ползунками и индивидуальными настройками и предупреждает, если текст попадает на вырез.
  • Производственные детали. Одинаковые детали группируются, имена файлов задаются шаблоном, несколько запущенных Tekla определяются, и нужный канал Open API выбирается автоматически.

Drawer

Автоматические сборочные чертежи и чертежи гнутых деталей · C# · Tekla Drawing API

  • Сборочные чертежи за один проход. Главный вид, виды сверху и снизу, автоматические разрезы по каждому узлу, 3D-вид, марки деталей на всех видах и формат листа, подобранный по размеру.
  • Перестроить, а не перечертить. У выбранных чертежей после изменений в модели заново создаются виды и размеры; для выбранных деталей создаются новые чертежи.
  • Гнутые детали как надо. Развёртка с образмеренными линиями гиба и виды гнутой детали с габаритами и радиусом гиба.
  • Стандарты компании соблюдаются. Используются файлы свойств видов, разрезов, размеров и компоновки, принятые в команде; по желанию — PDF для каждого чертежа.

Встроено в Tekla, раздаётся из одной папки

Вся команда работает на одних и тех же версиях без установщиков: общая папка на сервере, макросы-запускалки и своя вкладка в Приложениях и компонентах.

Собственные иконки макросов во вкладке компании в каталоге Tekla.

Макросы-запускалки

Маленький макрос на C# копирует exe с сервера в %LOCALAPPDATA%, только если копия на сервере новее, и запускает его. Файл на сервере никогда не блокируется, поэтому новую версию можно выложить в любой момент — она подхватится при следующем запуске.

Вкладка компании в каталоге

Собственный *_ComponentCatalog.ac.xml в папке фирмы добавляет вкладку с инструментами, общими компонентами и плагинами — с миниатюрами — в каждую модель у каждого пользователя.

Общие компоненты

Макрос импорта переносит пользовательские компоненты .uel из папки фирмы в открытую модель, никогда не перезаписывает уже существующие в ней компоненты, копирует миниатюры и предлагает сохранить модель.

Общие плагины

DLL плагинов раздаются на каждое рабочее место. Имена читаются из атрибута [Plugin] через загрузку только для чтения метаданных, а уже установленный плагин никогда не заменяется — поэтому существующие детали не перестраиваются и нумерация не ломается.

Папка фирмы и шаблоны

Одна папка XS_FIRM для атрибутов, шаблонов отчётов, чертежей и марок, подключённая в расширенных параметрах каждой модели, — с учётом ловушек, когда Tekla перезаписывает options.ini.

Публикация

Скрипт публикации копирует exe через временный файл и обновляет макросы и иконки, только когда меняется их хеш, поэтому пользователи никогда не получают недописанный файл.

Макрос-запускалка (C#, Tekla Akit) — схема, по которой работает каждая кнопка на панели 
// Запускает инструмент из общей папки макросов. Exe копируется в
// %LOCALAPPDATA% и запускается оттуда, поэтому копия на сервере не блокируется
// и её можно заменить в любой момент.
public static void Run(Tekla.Technology.Akit.IScript akit)
{
    string localDir = Path.Combine(Environment.GetFolderPath(
        Environment.SpecialFolder.LocalApplicationData), AppName);
    string localExe = Path.Combine(localDir, AppName + ".exe");
    try
    {
        Directory.CreateDirectory(localDir);
        if (NeedsUpdate(ServerExe, localExe))
        {
            // сначала во временный файл: обрыв сети не испортит рабочую копию
            string temp = localExe + ".new";
            File.Copy(ServerExe, temp, true);
            File.SetLastWriteTimeUtc(temp, File.GetLastWriteTimeUtc(ServerExe));
            try { File.Delete(localExe); File.Move(temp, localExe); }
            catch (IOException) { } // старая версия ещё открыта — обновится в следующий раз
        }
    }
    catch (Exception) { } // сервер недоступен — запускаем последнюю скопированную версию
    Process.Start(new ProcessStartInfo(localExe) { WorkingDirectory = localDir, UseShellExecute = true });
}

Плагины и макросы

Десять собственных плагинов Tekla (PluginBase с диалогами на WPF) моделируют узлы, которые команда повторяет сотни раз, поэтому они ставятся за секунды и всегда получаются одинаковыми.

  • Плагины кронштейнов — гнутый уголок-кронштейн между двумя трубами каркаса или в указанной точке: полки ложатся на грани элементов, линия гиба и расстановка отверстий рассчитываются, болты добавляются.
  • Плагины узлов ферм — семейство узлов для трубчатых ферм в четырёх вариантах.
  • Вырезы текста и профиля — гравировка текста и вырезы по форме профиля в пластинах.
  • Расстановка точек и инспектор для проверки параметров узлов в модели.
  • Макросы автоматизации интерфейса — например, скрытие переменных расстояний в редакторе пользовательских компонентов через Win32, когда API не даёт такой возможности.

Почему это важно

Плагин пересчитывается при каждом изменении модели. Если подложить на рабочее место новую версию плагина посреди проекта, детали могут незаметно перестроиться, а нумерация сломаться, — поэтому макрос раздачи только добавляет недостающие плагины и никогда не трогает установленные.
